## Method0

Code cstubs directly, write c code with ocaml functions annotation in order to covert ocaml types to c types and manage GC features and other ocaml things.

example: from `method0/mylib_stubs`
```c
CAMLprim value caml_hello_world(value unit)
```

declare signature in ocaml
```ocaml
external hello_world : unit -> unit = "caml_hello_world"
```

build: `bash compile.sh`, run: `./myprog`

The "c program" is compiled into objective file and then included in the objective file of the ocaml program.

### Cons:
Difficult to create c code that works well with ocaml, you have to do manually

## Method1

Call normal c programs using `ctypes` and `libffi` (dune project), in ocaml with `ctypes` declare bindings and types, at runtime with `libffi` convert types and call c code.

```c
void caml_hello_world(void)
```

```ocaml
let hello_world = foreign "caml_hello_world" (void @-> returning void)
```

build: `dune build`, run: `dune exec ./bin/myprog.exe`

### Cons:
Some error are only at runtime, slower: it has to comvert things at runtime

## Method2

Call normal c program using `ctypes` and `libffi` by generating `cstubs` at compile time using `dune` with a c external project. 

```c
#define FOO_VERSION 1

int foo_init(void);
```

```ocaml
open Ctypes

(* This Types_generated module is an instantiation of the Types
   functor defined in the type_description.ml file. It's generated by
   a C program that Dune creates and runs behind the scenes. *)
module Types = Types_generated

module Functions (F : Ctypes.FOREIGN) = struct
  open F

  let foo_init = foreign "foo_init" (void @-> returning int)
end

module Types (F : Ctypes.TYPE) = struct
  open F

  let foo_version = constant "FOO_VERSION" int
end
```

use in ocaml

```ocaml
C.Types.foo_version (*FOO_VERSION 1*)

C.Functions.foo_init () (*foo_init(void);*)
```

build: `dune build`, run: `dune exec ./foo.exe`

### Pro:
Error at compile time if not match, more speed, automatic
